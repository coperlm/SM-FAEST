## Phase 1：基础修复（最高优先级）

> 这三项是端到端签名无法工作的**根本原因**，必须首先解决。

### Task 1.1 — 添加 SM4 GF(2⁸) 域运算支持（已完成）

**完成情况**：在 `fields.c`/`fields.h` 新增 `bf8_mul_sm4()`、`bf8_square_sm4()`、`bf8_inv_sm4()`（多项式 0xF5），并在 `SM4_Constraints` 测试中复用。

- **验证结果**：SM4_Constraints PASS
- **涉及文件**：`fields.c`、`fields.h`、`tests/sm4_constraints.cpp`

### Task 1.2 — 修复 `sm4_invnorm()` 逆仿射变换（已完成）

**完成情况**：已使用 S-box + GF(2⁸)/0x1F5 逆元生成的查找表替代错误的仿射公式，SM4_Constraints 测试通过。

- **产出**：
  - `sm4_invnorm()` 使用 256 字节查找表
  - `tests/sm4_constraints.cpp` 同步使用相同查找表
- **验证结果**：SM4_Constraints PASS
- **备注**：查找表由 `tools/derive_sm4_affine.py` 生成并写入 `tools/sm4_invnorm_table.txt`

### Task 1.3 — 修复 `faest_impl.c` 签名调度（已完成）

**完成情况**：新增 SM4 分支调度，SM4 参数集走 `sm4_128_prover/verifier`。

- **验证结果**：待全链路验证（仍受 Phase 2 约束问题影响）
- **涉及文件**：`faest_impl.c`、`faest_sm4.h`

## Phase 2：ZK 约束系统修复

> Phase 1 完成后，才能有意义地调试和修复 ZK 约束逻辑。

### Task 2.1 — 修复 `column_to_row_major_and_shrink_V_128()`（已完成）

**完成情况**：已移植 AES 的逐位提取逻辑（列优先 → 行优先），修复 V 矩阵转换。

- **涉及文件**：`faest_sm4.c`

### Task 2.2 — 补全偶数轮 S 盒约束（已实现，待验证）

**完成情况**：偶数轮引入状态见证并通过 L^{-1} 推导 S 盒输出，补上逆范数约束。

- **验证状态**：待全链路验证（受其它约束问题影响）
- **涉及文件**：`faest_sm4.c`

### Task 2.3 — 修复密钥扩展反向传播（已实现，待验证）

**完成情况**：密钥扩展约束改为从轮密钥推导 `X` 与 `T'`，使用 `L'^{-1}` 得到 S 盒输出并生成逆范数约束。

- **验证状态**：待全链路验证
- **涉及文件**：`faest_sm4.c`

### Task 2.4 — 添加输出密文验证约束（已实现快速保护，待升级为ZK约束）

- **验证状态**：待升级为 ZK 约束
- **涉及文件**：`faest_sm4.c`

### Task 2.5 — 验证 β 常量正确性（已完成）

**完成情况**：已用 GF(2⁸)/0xF5 计算验证，常量正确，无需修改。
