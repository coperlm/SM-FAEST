## Phase 1：基础修复（最高优先级）

> 这三项是端到端签名无法工作的**根本原因**，必须首先解决。

### Task 1.1 — 添加 SM4 GF(2⁸) 域运算支持

- **问题**：`fields.c` 中 `bf8_modulus` 硬编码为 AES 的 `0x1B`（多项式 x⁸+x⁴+x³+x+1），SM4 需要 `0xF5`（多项式 x⁸+x⁷+x⁶+x⁵+x⁴+x²+1），当前整个文件无任何 SM4 域支持
- **影响**：`faest_sm4.c` 中所有 `bf8_mul`、`bf8_inv`、`bf8_byte_combine` 调用都在错误的域上运算
- **方案选择**（二选一）：
  - **方案 A**：在 `fields.c` 中新增 `bf8_mul_sm4()`、`bf8_inv_sm4()` 等函数，使用 `0xF5` 作为模多项式
  - **方案 B**：实现 SM4→AES 的同构映射矩阵（8×8 二元矩阵），将 SM4 域元素映射到 AES 域后复用现有 `bf8_mul`，运算完再映射回来
- **验证标准**：新域运算通过 GF(2⁸) 乘法单元测试（结合律/分配律/逆元）
- **涉及文件**：`fields.c`、`fields.h`，可能需要新增 `gen_sm4_constants.py` 生成映射矩阵

### Task 1.2 — 修复 `sm4_invnorm()` 逆仿射变换

- **问题**：`sm4.c:203` 中的逆线性变换公式 `z = rotl8(y,7) ^ rotl8(y,5) ^ rotl8(y,1)` 测试结果 **0/255 匹配**，完全错误
- **子问题**：
  - 仿射常量 `SM4_AFFINE_C = 0xD6`，但注释写 `0xD3`，两者矛盾且均未验证
  - 逆线性矩阵 L⁻¹ 的旋转组合公式不正确
- **修复步骤**：
  1. 确认 SM4 S 盒的仿射结构：S(x) = L(inv(x)) ⊕ c，其中 L 是 SM4 的线性变换矩阵
  2. 计算 L⁻¹ 的正确旋转分解
  3. 确认仿射常量 c 的正确值
  4. 修复 `sm4_invnorm()` 中的公式
- **验证标准**：SM4_Constraints 测试 **255/255 全部匹配**
- **涉及文件**：`sm4.c`、`tests/sm4_constraints.cpp`

### Task 1.3 — 修复 `faest_impl.c` 签名调度

- **问题**：`faest_impl.c` 中 `faest_sign` → `aes_prove()` → `aes_128_prover()` 是硬编码的，即使参数集为 `FAEST_SM4_128S` 也走 AES 路径；`sm4_128_prover` / `sm4_128_verifier` **从未被调用**
- **修复步骤**：
  1. 在 `faest_impl.c` 中添加 SM4 分支判断（根据 `instance` 参数集类型）
  2. 引入 `sm4_prove()` / `sm4_verify()` 或复用现有 `sm4_128_prover` / `sm4_128_verifier`
  3. 确保 `faest_sign` → `sm4_prove()` → `sm4_128_prover()` 的正确调用链
- **验证标准**：`faest_sm4_128s_api_test` 不再报 "Failed to verify (ret = -1)"（需配合其他修复）
- **涉及文件**：`faest_impl.c`、`faest_sm4.h`

## Phase 2：ZK 约束系统修复

> Phase 1 完成后，才能有意义地调试和修复 ZK 约束逻辑。

### Task 2.1 — 修复 `column_to_row_major_and_shrink_V_128()`

- **问题**：`faest_sm4.c:~1155` 使用 `V[i % 128][byte_idx]` 进行索引，而 AES 参考实现 `faest_aes.c.in` 使用 `ptr_get_bit(v[column], row)` 逐位提取——当前实现逻辑完全不同
- **修复**：从 `faest_aes.c.in` 的 `column_to_row_major_and_shrink_V_SSS()` 移植正确的逐位提取逻辑，适配 SM4 参数（`Nst=4, R=32` 等）
- **涉及文件**：`faest_sm4.c`

### Task 2.2 — 补全偶数轮 S 盒约束

- **问题**：`faest_sm4.c:~870` 偶数轮约束被跳过，注释 "简化实现：假设witness正确，直接使用temp作为S盒输出"，`(void)state_witness;` 证实 witness 数据未使用
- **修复**：偶数轮也必须生成完整的 S 盒非线性约束（inv_norm + 域逆 + 仿射变换），不能跳过
- **涉及文件**：`faest_sm4.c`

### Task 2.3 — 修复密钥扩展反向传播

- **问题**：`faest_sm4.c:~553` 的 `sm4_SSS_keyexp_backward_prover` 仅做 `memcpy`，验证器中 `(void)rk_key; (void)delta;` 证实无实际约束逻辑
- **修复**：参照 AES 版本的 `aes_key_schedule_backward` 实现 SM4 密钥扩展的反向约束推导
- **涉及文件**：`faest_sm4.c`

### Task 2.4 — 添加输出密文验证约束

- **问题**：`faest_sm4.c:~900` 中 `(void)owf_out; (void)owf_out_tag;`，最终加密输出从未与期望值进行比对
- **修复**：在约束末尾添加 owf_out 与计算结果的一致性检查（标量值相减为零的约束）
- **涉及文件**：`faest_sm4.c`

### Task 2.5 — 验证 β 常量正确性

- **问题**：`faest_sm4.c:162-173` 中 `sm4_beta_squares_gf8` 和 `sm4_beta_cubes_gf8` 的值需要在 SM4 GF(2⁸)（多项式 0x1F5）下验证正确性
- **修复**：编写脚本在 GF(2⁸)/0x1F5 下计算 β 的正确幂次，对照现有值修正
- **涉及文件**：`faest_sm4.c`、可能需要辅助 Python 脚本
