## 二、性能问题（已注意到速度变慢）

### 问题描述

当前 `sm4_SSS_linear_l_prover/verifier` 使用 **rotl32 方式**，每次调用：
- 在栈上分配 4 × 32 个 `bf128_t`（= 2048 字节栈空间）
- 调用 4 次 `sm4_SSS_rotl32_prover`（每次含复杂下标映射逻辑）
- `sm4_SSS_rotl32_prover` 内部有字位序转换（word_bit ↔ tag_index）

`sm4_SSS_linear_l_inv_prover/verifier` 使用**运行时掩码矩阵方式**：
- 首次调用触发矩阵求逆（GF(2)^{32×32} 高斯消元），结果静态缓存
- 每次调用：32 输出位 × 32 输入位 = 1024 次位运算（`sm4_parity32`）

### 性能改进方向（尚未实现）

**预计算静态路由表**（替换 rotl32 方式）：

对于 L（5个输入的异或）：每个输出位仅引用 5 个固定输入位

```c
// L(B) = B ⊕ B<<<2 ⊕ B<<<10 ⊕ B<<<18 ⊕ B<<<24
// 预计算：输出 tag[dst] = XOR of input tag[sm4_l_src[dst][0..4]]
static const uint8_t sm4_l_src[32][5] = { ... };
```

对于 L'（3个输入的异或）：

```c
// L'(B) = B ⊕ B<<<13 ⊕ B<<<23
static const uint8_t sm4_lp_src[32][3] = { ... };
```

这样避免栈上 bf128_t 数组、函数调用开销和复杂下标计算。

## 三、存在的健壮性缺陷（Soundness Bugs）

这是**最关键的待修复问题**。当前 ZK 证明系统存在两个漏洞，允许恶意 Prover 伪造证明：

### 缺陷 A：S-box 仿射约束缺失

**位置**：`sm4_SSS_enc_constraints_prover` 中奇数轮处理

**问题描述**：

当前代码从 witness 直接读取 `sbox_out`，但没有约束 `sbox_out` 确实等于 S-box 的输出：

```c
// 当前代码（有缺陷）：
sbox_out_odd[byte_i] = sbox_bytes[byte_i * 2];  // 直接读取，无约束！
```

正确做法（参考 AES 实现）需要添加仿射约束，即：

```
sbox_out = L(x^{-1}) ⊕ C
```

其中 `x` 是 S-box 输入，这等价于：
```
s = L^{-1}(sbox_out ⊕ C)  （逆仿射变换，已有实现）
s^{2^k} * y[k%4]  → 组合为 st_dash[k]
∑_k sm4_c[k] * st_dash[k]  = sbox_out（用 GF(2^128) 仿射约束检验）
```

**缺少的约束**：需要类似 AES 的 `sbox_affine` 约束，证明 sbox_out 与 invnorm 一致。

### 缺陷 B：偶数轮 state 未约束

**位置**：`sm4_SSS_enc_constraints_prover` 中偶数轮处理

**问题描述**：

```c
// 当前代码（有缺陷）：
memcpy(state, state_witness, 16);   // 直接用 witness 的 state，无约束！
memcpy(state_tag, state_witness_tag, 128 * sizeof(bf128_t));
```

Prover 可以写入任意 state（只要后续逆范数约束通过即可），完全绕过了 Feistel 方程：

```
new_state[0] = old_state[0] ⊕ L(τ(old_state[1] ⊕ old_state[2] ⊕ old_state[3] ⊕ rk))
```

**应该做的**：偶数轮的 new_word 应当直接从约束中**计算**得出，而不是从 witness 读取：

```c
// 正确做法：计算 new_word_even 并直接更新 state（不读 state_witness）
sm4_SSS_linear_l_prover(L_out_even, L_out_even_tag, sbox_out_even, sbox_out_even_tag);
new_word_even = state[0] ⊕ L_out_even;  // 由约束强制
// 然后 state 滚动更新，不依赖 witness
```

但问题是偶数轮的 `sbox_out_even` 不在 witness 中（witness 只为偶数轮存了 state）。解决思路：

**方案一**（修改 witness 布局）：为偶数轮也存 `sbox_out`（4字节），删除冗余的 `state`（16字节），节省空间，但需要修改 `sm4_extend_witness` 和 `Lenc`。

**方案二**（不改 witness 布局）：保持 state 在 witness 中，约束 `state_witness` 满足 Feistel 方程：即证明存在 `sbox_out_even` 使得 `state_witness[0] = state[0] ⊕ L(sbox_out_even)` 且 `sbox_out_even` 满足 S-box 约束。

## 五、关键技术参考

### SM4 S-box 结构

```
sbox(x) = L(x^{-1}) ⊕ C
```
- `C = 0xD6`（sbox(0) 的值）
- `L` 是 GF(2^8) 上的 8×8 线性变换（不同于 AES 的仿射矩阵）
- `L^{-1}(y)[i] = y[(i+1)%8] ⊕ y[(i+3)%8] ⊕ y[(i+7)%8]`（已在代码中用于 `inverse_affine`）

### AES sbox_affine 约束原理（SM4 需要移植）

```c
// AES 中：
// 1. 计算 temp 的 8 个 Frobenius 共轭：conj[k] = temp^{2^k}
// 2. 计算 invnorm 的 4 个共轭：y[i]（从 witness 的 invnorm）
// 3. st_dash[j] = conj[(j+4)%8] * y[j%4]  （度为2的乘积）
// 4. sbox_affine: ∑_k c[k] * st_dash[k]  → st_b（仿射变换结果）
// 5. 读取 witness 的 sbox_out = s_tilde
// 6. s = inverse_affine(s_tilde)
// 7. 三次约束: s^2 * st_b[0] = s  AND  s * st_b[1] = st_b[0]
```

SM4 的差异：无 ShiftRows/MixColumns，每轮只操作 1 个字（4字节），其余逻辑相同。

### witness 与约束的对应关系

| 轮次 | witness 内容 | 约束目的 |
|------|-------------|---------|
| 奇数（1,3,..,31） | 4字节 `sbox_out` + 4字节 `invnorm` | 约束 sbox_out 正确（仿射约束）|
| 偶数（2,4,...,30） | 16字节 `state` + 4字节 `invnorm` | 约束 state 满足 Feistel 方程（目前缺失）|
| 第32轮 | 4字节 `invnorm` | state 是公开输出 |
