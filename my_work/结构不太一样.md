### 二、 SM4 “1:3 方案”的逐轮阶数追踪（可行性证明）

我们设 SM4 的初始状态为四个 32 位的字 $X_0, X_1, X_2, X_3$，它们由明文或初始密钥生成，阶数均为 $deg = 1$。
SM4 的轮函数定义为：$$X_{i+4} = X_i \oplus L(S(in_i))$$，其中 $in_i = X_{i+1} \oplus X_{i+2} \oplus X_{i+3} \oplus RK_i$。

我们按 4 轮为一个周期，严格追踪内部变量的阶数变化：

#### **第 0 轮（引入期）：采用 4-bit `invnorm` 优化**
* **输入求值**：$in_0 = X_1 \oplus X_2 \oplus X_3$。因为 $X_{1,2,3}$ 均为 1 阶，所以 **$deg(in_0) = \max(1,1,1) = 1$**。
* **分配 Witness**：Prover 只提交 4 bits 的子域范数逆元 $c_0 = in_0^{-17}$。这是新鲜承诺，**$deg(c_0) = 1$**。
* **约束验证**：验证方程为 $c_0 \cdot in_0^2 \cdot in_0^{16} = in_0$。
    * 等式左边阶数 = $deg(c_0) + deg(in_0^2) + deg(in_0^{16}) = 1 + 1 + 1 = 3$。
    * **结论：最高 3 阶，约束合法！**
* **输出重构与状态更新**：
    * Verifier 在本地重构 S 盒完整输出：$out_0 = c_0 \cdot in_0^{16}$。
    * 注意升阶：$deg(out_0) = deg(c_0) + deg(in_0^{16}) = 1 + 1 = 2$。
    * 更新滑动窗口：$X_4 = X_0 \oplus L(out_0)$。因为 $L$ 是线性变换，**$deg(X_4) = \max(deg(X_0), deg(out_0)) = \max(1, 2) = 2$**。
* **当前窗口状态**：$(X_1^{D1}, X_2^{D1}, X_3^{D1}, X_4^{D2})$。（上标表示 Degree）

#### **第 1 轮（吸收期 1）：必须采用 8-bit `full` 约束**
* **输入求值**：$in_1 = X_2^{D1} \oplus X_3^{D1} \oplus X_4^{D2}$。此时 **$deg(in_1) = \max(1,1,2) = 2$**。（如果这里继续用 4-bit 优化，验证方程阶数将变成 $1+2+2=5$，直接崩溃）。
* **分配 Witness**：Prover 提交完整的 8 bits 输出 $y_1 = in_1^{-1}$。新鲜承诺，**$deg(y_1) = 1$**。
* **约束验证**：验证方程为 $in_1^2 \cdot y_1 = in_1$ 且 $in_1 \cdot y_1^2 = y_1$。
    * $in_1^2 \cdot y_1$ 的阶数 = $deg(in_1^2) + deg(y_1) = 2 + 1 = 3$。
    * $in_1 \cdot y_1^2$ 的阶数 = $deg(in_1) + deg(y_1^2) = 2 + 1 = 3$。
    * **结论：最高 3 阶，完美卡在系统极限，约束合法！**
* **状态更新**：$out_1$ 就是直接提交的 $y_1$，所以 **$deg(out_1) = 1$**。更新 $X_5 = X_1^{D1} \oplus L(out_1^{D1})$，得出 **$deg(X_5) = 1$**。
* **当前窗口状态**：$(X_2^{D1}, X_3^{D1}, X_4^{D2}, X_5^{D1})$。

#### **第 2 轮（吸收期 2）：必须采用 8-bit `full` 约束**
* **输入求值**：$in_2 = X_3^{D1} \oplus X_4^{D2} \oplus X_5^{D1}$，得出 **$deg(in_2) = 2$**。
* **分配 Witness**：提交 8 bits 输出 $y_2$。**$deg(y_2) = 1$**。
* **约束验证**：与第 1 轮同理，方程阶数为 $2 + 1 = 3$。**约束合法！**
* **状态更新**：$out_2 = y_2$ 是一阶，$X_6 = X_2^{D1} \oplus L(out_2^{D1})$，得出 **$deg(X_6) = 1$**。
* **当前窗口状态**：$(X_3^{D1}, X_4^{D2}, X_5^{D1}, X_6^{D1})$。

#### **第 3 轮（净化完成期）：必须采用 8-bit `full` 约束**
* **输入求值**：$in_3 = X_4^{D2} \oplus X_5^{D1} \oplus X_6^{D1}$，得出 **$deg(in_3) = 2$**。
* **分配 Witness**：提交 8 bits 输出 $y_3$。**$deg(y_3) = 1$**。
* **约束验证**：同理，方程阶数为 $2 + 1 = 3$。**约束合法！**
* **状态更新**：$out_3 = y_3$ 是一阶，$X_7 = X_3^{D1} \oplus L(out_3^{D1})$，得出 **$deg(X_7) = 1$**。
* **当前窗口状态**：$(X_4^{D2}, X_5^{D1}, X_6^{D1}, X_7^{D1})$。

#### **第 4 轮（新的循环）：再次安全使用 4-bit `invnorm` 优化**
* **输入求值**：$in_4 = X_5^{D1} \oplus X_6^{D1} \oplus X_7^{D1}$。
* **奇迹发生了**：此时 $X_4^{D2}$ 已经彻底滑出了输入计算的窗口！**$deg(in_4) = \max(1,1,1) = 1$**。
* 既然输入重新回到了纯净的 1 阶，我们就可以毫无顾忌地再次分配 4 bits 的 $c_4$，完美复刻第 0 轮的逻辑！

**数学推导结论**：通过严格的“1次 4-bit 配合 3次 8-bit”的交替排布，我们在 Feistel 网络的滑动窗口中完美地控制住了多项式阶数的膨胀。没有任何一个约束会超过 3 阶，该方案在代数层面上具备 100% 的可行性。
